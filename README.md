# 서울, 어디서 놀고 어디서 벌까?

공공데이터로 서울 상권을 분석하고, 소비자에게는 방문할 핫플을, 창업자에게는 업종별 창업 후보와 예상 월매출을 제공하는 프로젝트입니다.

- **서비스:** [서울 상권 분석 Streamlit 앱](https://dataseoul.streamlit.app/)
- **기존 발표자료:** [seoul_where_we_go.pptx](https://github.com/user-attachments/files/32836516/seoul_where_we_go.pptx)
- **분석 기준:** 2025년 1~4분기, 정제 데이터 84,675행, 고유 상권 1,577개, 고유 업종 62개
- **핵심 기술:** Python, pandas, scikit-learn, Streamlit, Altair, PyDeck, pyproj

## 1. 프로젝트 목적과 서비스

“사람이 많은 곳”이라는 한 가지 기준에서 벗어나, 사용자의 목적에 따라 같은 상권 데이터를 다르게 해석합니다.

| 사용자 | 의사결정 질문 | 제공 기능 |
| --- | --- | --- |
| 사장님 | 선택한 업종에서 매출·방문 수요·폐업점포 비율을 함께 비교하면 어디가 유리한가? | 업종별 창업 추천 TOP10, 평균 월매출, 유동인구, 2030비율, 폐업점포 비율, 예상 월매출, 지도 |
| 소비자 | 젊은층이 많이 활동하고 주말·저녁에도 활발한 곳은 어디인가? | 핫플 TOP20, 지도·점수 비교, TOP10 상세 조회, 지역별 인기 업종, 2030·주말·야간 지표 |

**창업추천점수와 핫플점수는 사람이 정한 가중치에 따른 규칙 기반 상대점수입니다.** 머신러닝은 별도로 점포당 월매출을 추정합니다. 소비자 질문 기능은 입력 키워드에 맞춰 저장된 데이터를 조회하는 방식이며 외부 생성형 AI API를 호출하지 않습니다.

## 3. 데이터 처리 방법

### 3.1 표준화

구현 근거: [01_check_data.py](src/01_check_data.py)

- 원천 CSV는 `cp949`로 읽고, 가공 결과는 `utf-8-sig`로 저장합니다.
- 연분기 코드에서 연도와 분기를 분리합니다. 예: `20251 → 2025년 1분기`.
- 연도는 `기준_년분기_코드 // 10`, 분기는 `기준_년분기_코드 % 10`으로 계산합니다.
- 2025년 점포 파일의 영문 컬럼을 공통 명칭으로 변경합니다. 예: `trdar_cd → 상권_코드`, `stor_co → 점포_수`.
- 코드에서는 `당월_매출_금액`을 `분기당_매출_금액`으로 바꾸고 월매출 계산 시 3으로 나눕니다. 이 해석은 **원천 데이터 설명의 분기 집계 단위와 대조가 필요**하며, 컬럼명 변경만으로 집계 정의가 검증되는 것은 아닙니다.

### 3.2 병합 기준과 분석 단위

최종 분석 한 행의 단위는 **연도 × 분기 × 상권 × 업종**입니다.

| 단계 | 병합 키 | 방식과 목적 |
| --- | --- | --- |
| 매출 + 점포 | 연도, 분기, 상권 코드, 서비스 업종 코드 | 매출을 기준으로 left merge |
| 위 결과 + 유동인구 | 연도, 분기, 상권 코드 | 동일 시점의 상권 인구 연결 |
| 추천 결과 + 위치 | 상권 코드 | 위도·경도·자치구·행정동 연결 |

현재 코드에서는 `validate="many_to_one"`으로 우측 키 중복에 따른 행 증가를 막습니다. 사용 원본의 매출·점포·유동인구 병합 키 중복은 각각 0건으로 확인했습니다.

유동인구는 상권 단위라 여러 업종 행에 같은 값이 반복됩니다. 핫플 계산에서는 업종별 반복을 제거하고 **상권·분기 단위**로 계산합니다.

### 3.3 결측·중복·분모 0 처리

구현 근거: [02_clean_data.py](src/02_clean_data.py)

| 구분 | 결과 |
| --- | ---: |
| 정제 전 `final_mart.csv` | 85,732행 × 26열 |
| 점포당 월매출 결측 | 1,036행 |
| 총 유동인구·2030비율 결측 | 각각 21행 |
| 핵심 지표 결측으로 제외한 행 | 1,057행, 원본의 약 1.23% |
| 정제 후 `clean_mart.csv` | 84,675행 × 26열 |
| 정제 후 전체 결측 셀 / 완전히 동일한 행 중복 | 0개 / 0행 |

`점포당_월매출`, `총_유동인구_수`, `2030비율` 중 하나라도 결측이면 제외합니다. 나눗셈 전 분모 0은 `pd.NA`로 바꾸며, 임의의 0으로 채우지 않습니다.

정제 데이터의 분기별 행 수는 Q1 **21,170**, Q2 **21,186**, Q3 **21,256**, Q4 **21,063**입니다. 고유 상권 1,577개와 업종 62개를 포함하지만, 모든 상권에 모든 업종이 있는 완전한 패널은 아닙니다.

### 3.4 핵심 파생변수

| 지표 | 계산 방법 | 해석 |
| --- | --- | --- |
| 객단가 | 분기 매출금액 ÷ 매출건수 | 거래 1건당 평균 금액 |
| 점포당 분기매출 | 분기 매출금액 ÷ 점포 수 | 상권·업종별 점포당 평균 |
| 점포당 월매출 | 점포당 분기매출 ÷ 3 | 분기 수치를 월 단위로 환산한 평균 |
| 2030비율 | (20대 + 30대 유동인구) ÷ 총 유동인구 × 100 | 젊은 연령층 비중 |
| 폐업점포 비율 | 폐업 점포 수 ÷ 점포 수 × 100 | 코드의 `폐업비율` 컬럼 |
| 주말 유동인구 | 토요일 + 일요일 유동인구 | 주말 활동량 |
| 야간 유동인구 | 17~21시 + 21~24시 유동인구 | 코드에서 정의한 저녁·야간 활동량 |

폐업점포 비율은 개별 점포의 생존확률이나 미래 폐업확률을 의미하지 않습니다. 유동인구 역시 원천의 추정·집계 정의를 확인하기 전에는 고유 방문자 수로 단정하지 않습니다.

## 4. 추천 점수 설계

### 백분위 점수

원·명·%처럼 단위가 다른 지표를 `series.rank(pct=True) * 100`으로 변환합니다. 동점은 pandas 기본 평균 순위를 사용합니다. 폐업비율은 낮을수록 높은 점수를 받도록 `100 - 백분위점수`를 적용합니다.

이 점수는 관측 데이터 안에서의 상대적 위치입니다. 성공확률이나 절대 품질 점수가 아니며, 최솟값이 반드시 0점인 산식도 아닙니다.

### 창업추천점수

구현 근거: [04_better_score.py](src/04_better_score.py), [06_final_startup_ranking.py](src/06_final_startup_ranking.py)

```text
창업추천점수 =
    매출점수 × 0.40
  + 유동인구점수 × 0.25
  + 2030점수 × 0.20
  + 폐업안정점수 × 0.15
```

1. 정제된 전체 분기·상권·업종 행을 기준으로 백분위를 계산합니다.
2. 분기별 점포 수가 3개 이상인 관측값만 후보로 남깁니다.
3. 상권·업종별로 추천점수, 월매출, 유동인구, 비율의 기간 평균을 계산합니다.
4. 서비스에서는 사용자가 선택한 업종 안에서 평균 추천점수 상위 10개를 표시합니다.

최종 상권·업종 조합은 **20,933개**입니다. 일부 분기만 점포 수 조건을 통과할 수 있으므로, 평균에 사용된 관측 분기 수를 공개하는 개선이 필요합니다. 현재 백분위는 동일 업종 안에서만 계산한 점수가 아닙니다.

저장된 전체 업종 통합 테이블의 상위 사례:

| 상권 | 업종 | 평균 추천점수 |
| --- | --- | ---: |
| 신촌역(신촌역, 신촌로터리) | 의약품 | 91.04 |
| 잠실 관광특구 | 완구 | 90.96 |
| 신림역 5번(신림동주민센터, 신림동별빛거리) | 슈퍼마켓 | 90.78 |

### 핫플점수

구현 근거: [05_hotplace_score.py](src/05_hotplace_score.py)

```text
핫플점수 =
    전체유동점수 × 0.35
  + 2030점수 × 0.30
  + 주말점수 × 0.20
  + 야간점수 × 0.15
```

상권·분기 단위 **6,271행**에서 각 지표의 백분위를 구하고, 서비스에서는 최신 분기만 골라 TOP20을 표시합니다. 백분위 산출 범위는 최신 분기 하나가 아닌 전체 보관 분석 분기입니다.

| 2025 Q4 순위 | 상권 | 핫플점수 |
| --- | --- | ---: |
| 1 | 신촌역(신촌역, 신촌로터리) | 99.69 |
| 2 | 홍대입구역(홍대) | 99.13 |
| 3 | 신림역 5번(신림동주민센터, 신림동별빛거리) | 98.89 |

총량·주말·야간 지표는 서로 관련되어 방문량의 영향이 중첩될 수 있습니다. 또한 코드가 다른 인접 상권은 별도 후보로 취급하므로, 역 단위 통합 순위와 구분해야 합니다.

## 5. 지도 좌표 처리

| R² | 0.5227 |

**저장 결과는 현재 Q4 평가 후보보다 219행 적습니다.** 따라서 위 수치는 기존 평가 표본의 결과이며, 현재 코드로 전체 Q4를 재평가한 성능으로 해석하면 안 됩니다. 현재 코드로 모델을 재학습하거나 평가 결과를 재생성하지 않았습니다.

R² 0.5227은 “정확도 52.27%”가 아니라, 해당 평가 표본의 매출 변동을 약 52.3% 설명했다는 의미입니다. MAE와 RMSE도 함께 확인해야 실제 오차의 크기를 판단할 수 있습니다.

또한 Q4 평가에는 **Q4의 유동인구·점포 수 등 같은 분기의 실측 입력**이 사용됩니다. 이 정보를 미리 알 수 없는 상황의 사전 미래 예측 성능으로 단정할 수 없습니다.

### 최종 모델과 화면 입력

최종 모델 코드는 전체 데이터에서 결측을 제거하고 월매출 상위 1% 초과를 제외해 서비스용 모델을 학습합니다. 이 단계는 별도 성능 평가가 아닙니다.

화면에서는 상권·업종별 평균 유동인구·점포 수·비율을 학습 컬럼명으로 바꿔 모델에 넣습니다. 평균 입력의 예측값은 분기별 예측의 평균과 다를 수 있습니다. 저장된 pkl과 현재 코드의 학습 이력 일치 여부도 별도 확인이 필요합니다.

## 9. 로컬 실행과 검증

Python 3.12에서 실행 및 검증했습니다. 저장된 모델과의 호환성을 위해
`scikit-learn` 버전을 유지하세요.

```bash
python3.12 -m venv /workspace/venvs/data_seoul
/workspace/venvs/data_seoul/bin/python -m pip install -r requirements.txt
/workspace/venvs/data_seoul/bin/python -m streamlit run src/app.py --server.headless=true --browser.gatherUsageStats=false
```

저장소 루트에서 실행하는 것을 권장합니다. 앱은 포함된 가공 데이터와 학습 모델을
사용하므로 최초 실행을 위해 전처리 또는 재학습할 필요가 없습니다.
소비자 질문 기능은 키워드 기반 데이터 조회이며 외부 AI API 키가 필요하지 않습니다.
`src/01_*.py`부터 `src/12_*.py`까지는 데이터 처리 및 학습 스크립트로,
실행하면 가공 데이터나 모델 파일을 덮어쓸 수 있습니다.

앱의 두 모드, 매출 예측, 질문 조회, 상세 선택을 검증하려면:

```bash
/workspace/venvs/data_seoul/bin/python -m unittest discover -s tests -v
```

## 10. 코드 구성 및 재현 범위

- `src/app.py`: 사장님/소비자 화면과 공통 지도·점수 그래프·지표 카드 함수.
- `assets/styles.css`: 배경, 카드, 모드 토글 스타일. 스타일을 바꾸면 실행 중인 앱을 재시작하세요.
- `src/01_*.py`~`src/08_*.py`: 데이터 병합, 정제, 점수 계산 및 지도 좌표 생성.
- `src/09_*.py`~`src/12_*.py`: 기본 모델, 개선 모델, 시간 기준 평가, 최종 모델 학습.

번호가 붙은 스크립트는 직접 실행할 때만 처리하며, 다른 코드에서 import해도
데이터 생성이나 모델 학습을 시작하지 않습니다. 데이터·모델 경로는 각 파일의
위치를 기준으로 계산하므로 실행 디렉터리에 영향을 받지 않습니다.

개선 모델 및 시간 기준 평가의 이상치 기준은 학습 데이터에서만 계산하며,
평가 데이터는 제거하지 않습니다. 이 변경은 다음 평가 실행부터 적용됩니다.
기존 가공 CSV 및 저장된 모델을 이번 코드 정리 과정에서 재생성하지 않았습니다.

테스트는 두 모드의 주요 기능, 좌표 누락, 공백 질문, 동일값 점수 계산,
스크립트 import 시 부작용, 미래 분기 평가 데이터 유지 여부를 확인합니다.
전체 모델 재학습이나 브라우저의 실제 CSS 렌더링 검증은 포함하지 않습니다.

이 문서의 데이터 규모·결측·중복·추천 사례는 저장소의 CSV와 처리 코드를 대조한 결과입니다. 모델 성능은 기존 저장 예측 결과를 재계산했으며, 이번 문서 수정에서 데이터 재수집·모델 재학습·배포 상태 확인은 수행하지 않았습니다. 기존 발표자료의 수집 출처 표기와 실제 확인된 파일·코드 범위를 구분했습니다.
